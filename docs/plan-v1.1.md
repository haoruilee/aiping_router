## 本版本变更概览

| 变更点 | v1.0 | v1.1 | 原因 |
|--------|------|------|------|
| 默认路由阈值 | 50 | **85** | 确保约 90% 请求走本地 |
| Token 触发阈值（高） | 2000 | **4000** | 中等长度对话不应走云端 |
| Token 触发阈值（低） | 500 | **1500** | 起始计分位提高 |
| 代码复杂度触发行数 | 30 | **80** | 小代码片段本地完全可处理 |
| 推理关键词策略 | 单词即触发 | **强多词短语才触发** | 日常"分析"类问答应走本地 |
| 多轮上下文阈值 | 6 轮 | **16 轮** | 普通多轮对话不走云端 |
| 配置向导语言 | 英文 | **全中文，详细引导** | 面向中文用户 |
| 首次安装行为 | 触发向导 | **触发中文向导 + 设置默认模型** | 开箱即用体验 |
| 默认模型设置 | 无 | **自动尝试设置 aiping:claw 为默认** | 零配置开始使用 |

## 1. 路由阈值调整详解

### 设计目标

以 85 分为阈值，在满分 85 分的评分体系下，只有同时满足多个重量级条件的请求才能到达云端：

```
理论最高分 = 30 (token) + 20 (代码) + 15 (推理) + 20 (多轮) = 85 分
```

**典型请求分布估算**：

| 请求类型 | 估算得分 | 路由结果 |
|---------|---------|---------|
| 日常对话（"你好"、"帮我写个函数"） | 0–10 | ✅ 本地 |
| 中等代码问题（< 80 行代码）| 5–20 | ✅ 本地 |
| 多轮聊天（< 16 轮）| 5–25 | ✅ 本地 |
| 长上下文（2000–4000 tokens）| 10–29 | ✅ 本地 |
| 强推理关键词（如"逐步分析"）| 15 | ✅ 本地（单独不够） |
| **重度任务**：超长 + 大代码 + 强推理 + 超多轮 | **≥85** | ☁️ 云端 |

## 2. 推理关键词策略调整

**v1.0** 用单词（如"分析"、"compare"）即触发 +15 分。这导致大量普通提问误判为复杂任务。

**v1.1** 只有明确多词重量级短语才触发：

```
// 中文强关键词（新）
'详细分析', '逐步分析', '全面对比', '深度分析', '系统性分析',
'优缺点对比', '深入推理'

// 英文强关键词（保留）
'explain in detail', 'step by step', 'reason through',
'pros and cons', 'trade-offs', 'critically evaluate'
```

这样"帮我分析这段代码"不触发（单独的"分析"不在列表），但"请深度分析这段代码的性能问题"会触发。

## 4. 默认模型设置机制

安装完成后，`aiping:claw` 自动成为默认模型。实现分两层：

**层 1（优先）**：通过 OpenClaw Gateway API
```typescript
if (typeof api.setDefaultModel === 'function') {
  api.setDefaultModel('aiping:claw');
}
```

**层 2（兜底）**：向导询问用户并写入配置文件
```
候选路径：
  ~/.openclaw/config.json
  ~/.config/openclaw/config.json
写入内容：{ "defaultModel": "aiping:claw" }
```

若两者均失败，向导会打印手动命令：
```bash
openclaw config set defaultModel "aiping:claw"
```
